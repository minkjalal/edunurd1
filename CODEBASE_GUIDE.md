# EduNerd codebase and connection guide

This document explains how the maintained source files connect. The React source under `src/` is the behavior source of truth; `public/bundle.js` is generated by `build.js` and should not be edited by hand.

## Runtime map

```text
Browser :3210
  -> public/index.html + public/bundle.js
  -> src/index.jsx
  -> src/App.jsx
  -> AppContext + route views
       |-> server.js :3210/api/*        local auth, storage, and offline /api/ai fallback
       |-> backend/server.py :8000       Groq tutor, audits, study plans, flashcards
       |-> sidecar/chat-server.js :3001  community REST + WebSocket chat
       `-> browser APIs                  localStorage, Web Audio, notifications, speech, YouTube
```

The browser keeps the session and learner progress in `localStorage` through `AppContext`. Views read that shared state and call context actions instead of maintaining separate copies. Tutor responses arrive from FastAPI, then `AITutorView` sends flashcards, XP, and community-share triggers back into the context. The Node server provides the older generic AI route and returns the deterministic offline tutor whenever Gemini is unavailable. The chat sidecar is intentionally separate so community presence and WebSocket traffic cannot block the main app.

## Request and state flows

### Tutor and study-plan flow

1. `src/views/AITutorView.jsx` sends `{ query, provider: "groq", primary_model }` to `backend/server.py:/api/tutor`.
2. `backend/server.py` drafts with the selected Groq model, retries transient failures, and runs a second consistency pass.
3. The verdict is rendered in the tutor answer card. `flashcard_export` calls `AppContext.pushFlashcards`; `gamification_triggers` calls the XP and sharing actions.
4. If the request cannot reach FastAPI or Groq, the view renders an honest local framework and keeps retrying the health endpoint.
5. `src/views/DashboardView.jsx` sends class, exam goal, topic, weak topics, and goal minutes to `/api/study-plan`; each returned activity is mapped to an internal route before navigation.

### Offline AI flow

`server.js:/api/ai` is a local fallback API. It accepts the same message shape used by the older tutor surfaces and calls `offlineTutor()` when no Gemini key exists or the remote request fails. This route is independent of the Groq tutor route, so a Groq outage does not remove the local study framework.

### Flashcard flow

`src/views/FlashcardsView.jsx` owns deck navigation and custom cards. Its generator calls `backend/server.py:/api/flashcards/generate`; returned cards are normalized and appended through `AppContext.pushFlashcards`, preserving existing cards.

### Progress, timer, and rewards flow

`StudyTimerView`, dashboard manual logging, and YouTube playback all call `AppContext.recordStudyMinutes`. The context updates the daily goal, streak, XP, badges, and reset state in one place. `RewardsView` reads those derived values and exposes downloadable badge artifacts.

### Community flow

`CommunityView` owns channel/server presentation and uses `communityModeration.js` before a message enters local history. The people-chat feature uses `features/people-chat/chatService.js` for its REST/WebSocket boundary. The optional sidecar persists its own `sidecar/chat-data.json`, verifies the shared JWT secret, and exposes `/health`, `/api/chat/*`, and `/ws/chat`.

## Maintained module catalog

### Application shell and shared UI

- `src/index.jsx` mounts the React root and global CSS.
- `src/App.jsx` supplies `AppProvider`, shared chrome, and hash-route selection.
- `src/context/AppContext.jsx` is the single source for session, progress, flashcards, goals, rewards, timers, toasts, and navigation actions.
- `src/components/Header.jsx`, `NavigationDrawer.jsx`, `BrandLogo.jsx`, and `TutorLogo.jsx` render shared branding and navigation.
- `src/components/AmbientBackground.jsx`, `RobotEyes.jsx`, `ToastContainer.jsx`, and `TimerModal.jsx` provide global visual and feedback primitives.

### Views

- `AITutorView.jsx`: online/offline tutor UI, audit rendering, math text normalization, and voice input.
- `DashboardView.jsx`: progress cockpit, Groq study-plan form, notes, weak-topic tracking, and internal activity links.
- `StudyView.jsx`: tutor, flashcard, and Pomodoro tab composition.
- `FlashcardsView.jsx`: active-recall deck, custom cards, and FastAPI card generation.
- `StudyTimerView.jsx`, `TimerView.jsx`: Pomodoro phases, ambient sound, notifications, and recorded study minutes.
- `CommunityView.jsx`: cohort-aware Discord-style community channels, moderation, audio, and local history.
- `VideosView.jsx`, `PYQView.jsx`, `ResourcesView.jsx`, `VideoResourceExplorer.jsx`, and `LibraryView.jsx`: learning resources and safe internal destinations.
- `RewardsView.jsx`, `CalendarView.jsx`, `CompetitionView.jsx`, `QuizView.jsx`, and `ClassZoneView.jsx`: rewards, planning, tests, quizzes, and class-specific study tools.
- `LoginView.jsx`, `WelcomeView.jsx`, `NotesView.jsx`, `OfflineView.jsx`, and `VisualLearningView.jsx`: session entry, notes, local mode, and simulations.

### Domain utilities and features

- `src/utils/helpers.js`: route, date, level, and formatting helpers used by views and context.
- `src/utils/communityModeration.js`: cohort policy, abuse detection, sanitization, and message length limits.
- `src/utils/questionGenerator.js`: deterministic local question generation for class and exam tools.
- `src/utils/sound.js` and `confetti.js`: browser-only feedback effects.
- `src/constants/*.js`: static navigation, exam, platform, simulation, badge, and flashcard definitions.
- `src/features/people-chat/*`: direct-message UI, safety flags, profile/directory tabs, and chat transport.
- `src/features/chatbot-mascot/*`: optional mascot observer, runner, state flags, and presentation styles.

### Server and build layer

- `server.js`: Express static host, auth, document storage, generic `/api/ai`, and deterministic offline tutor.
- `backend/server.py`: FastAPI schemas and endpoints for tutor audits, study plans, flashcards, health, and Groq integration.
- `backend/agents.py`, `rag_engine.py`, and `tutor_engine.py`: reusable verification, retrieval, and tutor helpers used by the FastAPI layer.
- `sidecar/chat-server.js`: isolated community REST/WebSocket service; `sidecar/schema.sql` documents its relational shape and `sidecar/README.md` documents its contract.
- `build.js`: esbuild entry point from `src/index.jsx` to `public/bundle.js`.
- `run_ag2.py`, `start-all.js`, and `run-local.bat`: local process runners. Use the runner that matches the desired frontend port; all service URLs are documented above.

## Commenting convention

Each maintained source file has a module connection note. Comments should describe why a boundary exists, the shape of data crossing it, and which consumer owns the next step. Avoid comments that merely repeat the syntax. Keep generated bundles, lockfiles, logs, caches, and image assets out of hand-written documentation.
